`submitQueuedAction` and `submitSerializedSetupAction` return derived queue receipts. Their checker entries prohibit owned-domain workflow calls even through aliases or local helpers. Ordinary pool/status forwarding APIs, the report command-to-helper-arguments round trip, the case request-type map and handwritten fallback are removed. Remaining queue adapters own identifiable translation, admission, serialization or fixture presentation work.

The bot accepts a narrow derived `QueuedRequestRuntime`. Its single exhaustive `queuedActionHandlers` registry prepares request-bound executors, and `prepareQueuedRequest` returns only `execute` plus an optional completion hook. Cleanup, CAPTCHA, quarantine and detection factories bind the same claimed row once; preparation neither replaces application methods nor grants execution authority. The worker preserves heartbeat/attempt ownership, confirmed and uncertain recovery, and completion-before-hook ordering. `PreparedQueuedRequest.unit.test.ts`, the forty independent stored-row fixtures and eighty unchanged snapshots, parity tests, and service recovery/hook tests cover these contracts.

Production source uses the existing metrics exclusions: `src`, `apps/web/app`, `apps/web/lib`, `packages/contracts/src`, and `packages/application/src`; generated/build/dependency directories and tests/specs are excluded. Compared with merged base `f1853d0`, production changes from 301 files / 89,201 physical lines to 303 files / 88,951 lines: two more files and 250 fewer lines. Dedicated authority, typed submission and exhaustive translation modules replace two member wrappers and duplicated submission/runtime composition. Cohesive CAPTCHA/quarantine translators keep the outer exhaustive case switch at CCN 17; the unchanged production gate remains CCN 25 / length 300. Test/docs growth is excluded from this reduction.
